# 检索以 PostgreSQL 权威资料和知识库发布快照保持一致

检索规格 [#82](https://github.com/yb2915722928-cpu/rag_me/issues/82) 要求向量、BM25、FAQ 和父块读取使用同一可见资料范围，因此 PostgreSQL 保存正文、来源、完整证据身份和父子关系，pgvector 与 pg_search 分别保存派生向量和 BM25 索引；父正文不以生成向量为前提。每个知识库独立准备并发布快照，必需索引就绪后原子切换发布指针，查询固定各库快照和当前时间，失败保留旧完整快照。

选择 pg_search 与 Jieba，是因为 PostgreSQL 内置全文评分不是 BM25，而额外独立检索后端会增加跨存储同步责任；代价是扩展安装、升级和兼容版本维护。BM25 分析器配置和语料统计范围固定于知识库快照，文档与 FAQ 问法分别排名；已接受 Windows 应用搭配受支持 Linux 数据库环境，但本阶段只开发功能与测试代码，不安装服务、不运行测试或部署，接口与性能均未实际验证。

本决策承接 2026-11-02 已确认的检索快照决策，以连续编号 0004 纳入已包含两个上游索引 ADR 的集成分支。它细化并部分取代 [ADR-0003](0003-retrieval-handoff-contract.md) 第 3–5 项：索引身份仍包含 scheme_identity 并用于隔离向量空间；融合证据身份使用知识库、文档及修订、块及修订，FAQ 使用知识库、条目及修订，因此同一证据的不同方案命中可以合并展示且保留所有方案依据。快照选择明确的索引绑定，不用全局活动方案推断业务版本；查询编码继续复用模块 3 的公开边界，必要的快照持久化与完整结构化过滤由模块 4 的实际适配器承担，旧模块 3 调用契约保持可用。
