# ZIP 容器默认采用托管文档和多模态解析

ZIP 功能将部署到低配置服务器，用户明确要求有合适 API 时默认使用 API。ZIP 内 PDF（包括数字 PDF）、DOCX、PPTX、XLSX、HTML 的解析交给既有 MinerU 托管服务，MHTML 只在本地选取主 HTML 后提交；图片和音视频模型计算使用既有阶跃 API。本地仅承担容器管理、轻量文本/结构处理以及现有媒体准备，不部署文档或多模态模型，API 配置缺失或失败也不自动回退成本地重解析。

代价是依赖外部服务，且云端 Office 结果不一定提供原生单元格、正文块或对象位置；因此保留真实返回的来源粒度并报告缺失，不伪造本地解析器曾提供的位置。这个约束适用于 ZIP 集成，不改写其他独立格式模块的默认路线。正式需求见 [规格 #39](https://github.com/yb2915722928-cpu/rag_me/issues/39)，服务能力以 [MinerU 托管 API 文档](https://mineru.net/apiManage/docs)为准。
