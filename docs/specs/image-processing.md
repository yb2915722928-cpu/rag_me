# 图片处理：三类视觉任务、原图追溯与待核验结果

> 已发布：[GitHub Issue #27](https://github.com/yb2915722928-cpu/rag_me/issues/27)，标签：enhancement、ready-for-agent。

## Problem Statement

知识库开发者需要把截图、扫描图片、流程图及其他独立图片转为可供后续 RAG 使用的图片派生文字，并能从文字回查对应原图。只识别框内文字无法证明条件与箭头的对应，主题描述也不能替代具体问题下的视觉理解；生成内容可能遗漏否定、扩大条件或添加原图不存在的关系。

当前独立图片处理模块只有占位内容。扫描 PDF 已有 MinerU 识字实现，演示文稿可以记录图片来源和待核验关系，但尚无独立图片的文件／字节处理入口，也没有图像描述或针对问题的单图视觉理解。

本规格最初由需求访谈形成。用户随后确定使用阶跃星辰，报告已完成本地环境配置，并于 2026-10-28 授权按关联子事项实施；实现仍限定在指定图片处理模块。

## Solution

提供独立图片的公开文件入口与字节入口，一次显式执行图像识字（OCR）、图像描述或视觉理解中的一种任务。三种任务统一使用用户提供的一个视觉 API。OCR 获取图片文字，图像描述提供检索主题线索，视觉理解直接结合原图与具体问题解释内容和关系。

返回图片派生文字、图片版本标识、实际输入来源、可选原文档来源、原图映射、处理信息及独立诊断。完成处理、没有识别到文字、无法确认关系与调用失败分别表达；所有模型产出保留待核验状态，能定位来源不代表内容已经被验证。

首版止于图片处理与表示。下游负责存储原图、切块、索引、召回和完整 RAG 问答。

## User Stories

1. As a 知识库开发者, I want 通过文件入口处理独立图片, so that 本地截图和扫描图片可以成为后续 RAG 的输入。
2. As a 调用方, I want 通过字节入口处理已取得的图片, so that 不必先为上传内容创建临时文件。
3. As a 调用方, I want 文件与字节入口遵循同一契约, so that 来源相同的输入可以得到等价结果。
4. As a 调用方, I want 处理静态 PNG、JPEG 和 WebP, so that 常见截图与图片文件得到明确支持。
5. As a 调用方, I want 一次明确选择一种视觉任务, so that 处理目的和模型调用范围可预期。
6. As a 知识库开发者, I want 从图片识别文字, so that 图片中的文字可以作为后续文字检索的入口。
7. As a 内容核验者, I want OCR 尽量保留条件、否定、数字及单位, so that 文字变化不会悄悄改变业务含义。
8. As a 知识库开发者, I want 获得图片主题与画面的描述, so that 用户可以通过主题文字寻找相关图片。
9. As a 内容核验者, I want 主题描述与识字结果保持任务区别, so that 概括不会冒充图片原文。
10. As a 调用方, I want 把具体问题与图片一起交给视觉理解, so that 可以分析图中的条件、箭头和节点关系。
11. As a 调用方, I want 视觉理解要求非空问题, so that 系统不会自行猜测要回答什么。
12. As a 内容核验者, I want 视觉理解直接检查本次输入原图, so that 错误的旧描述不会代替图片成为关系判断依据。
13. As a 内容核验者, I want 审批图的两个分支分别保留条件与审批人对应, so that 一个分支不会被扩成所有情况通用的规则。
14. As a 调用方, I want 模糊、截断或缺失的关键关系明确表示无法确认, so that 下游可以保留不确定性。
15. As a 调用方, I want 未识别到文字与调用失败分别表达, so that 正常空识字结果不会被误当成网络或鉴权故障。
16. As a 调用方, I want 无法确认的结果保留原因与来源, so that 可以寻找完整或更清晰的原图继续核验。
17. As a 内容核验者, I want 所有模型产出保留待核验状态, so that 调用成功不会被误解释为事实已经核验。
18. As a 内容核验者, I want 高置信度不自动清除待核验状态, so that 模型自评不会冒充正确性证明。
19. As a 下游开发者, I want 取得图片实际字节的 SHA-256, so that 能区分同名图片的不同字节版本。
20. As a 调用方, I want 来源保留输入文件或调用方提供的来源标识, so that 能定位本次实际处理的图片。
21. As a 调用方, I want 可选提供所属文档标识和业务版本, so that 派生文字可以关联回原文档。
22. As a 内容核验者, I want 来源明确区分实际 PDF 页序和幻灯片位置, so that 不会用模糊的页号混淆不同原文档位置。
23. As a 调用方, I want 独立图片无需虚构页号或父文档, so that 没有的来源信息保持未知。
24. As a 内容核验者, I want 缺失的文档版本不从文件名猜出, so that 来源元数据不会伪装成已知事实。
25. As a 调用方, I want 处理已经裁剪的图片并提供原图映射, so that 派生文字仍能回查原图中的真实区域。
26. As a 内容核验者, I want 裁剪区域采用明确的原图像素坐标, so that 不会把裁剪图局部坐标冒充原图坐标。
27. As a 内容核验者, I want 整图描述关联整图或已知裁剪区域, so that 系统不会无依据生成更细的定位。
28. As a 下游开发者, I want 结果记录任务类型、模型和提示词版本, so that 可以理解不同处理结果的产生方式。
29. As a 内容核验者, I want 视觉理解结果保留本次问题, so that 可以回查解释所回答的具体条件。
30. As a 下游开发者, I want 正文、来源、待核验事项、普通警告和错误分开返回, so that 诊断不会进入知识正文。
31. As a 调用方, I want 损坏图片、格式不符和非法选项明确失败, so that 无效输入不会被提交为正常视觉任务。
32. As a 调用方, I want 缺少 API 配置、鉴权失败、超时及无效响应给出可识别诊断, so that 可以判断是否需要补配置或稍后重试。
33. As a 项目维护者, I want 三种任务接入同一个由用户提供的视觉 API, so that 首版不承担多提供方路由或 PDF 模块改造。
34. As a 用户, I want 实施进入模型接入时暂停等我提供 API, so that 所用服务由我确定。
35. As a 测试维护者, I want 下载及构造的图片固定保存在约定样本目录, so that 测试输入便于检查、复用和回查。
36. As a 测试维护者, I want 下载样本记录原始来源、许可、大小与 SHA-256, so that 可以核对样本身份与使用条件。
37. As a 测试维护者, I want 默认测试通过本地 HTTP 服务运行真实客户端和模块入口, so that 无需消耗外部 API 也能验证协议与结果表达。
38. As a 内容核验者, I want 对固定图片进行真实 API 验收, so that 能检验 OCR 文字、主题描述、审批分支和模糊图处理的实际质量。
39. As a 项目维护者, I want 离线协议测试与真实视觉质量验收分别记录, so that 固定返回值不会被当成真实识别能力证明。
40. As a 下游开发者, I want 取得图片派生文字及其来源但不被迫接入索引服务, so that 后续 RAG 可以独立选择切块和检索方式。

## Implementation Decisions

- 业务实现集中在独立图片处理模块。公开文件入口和字节入口沿用相邻解析模块的调用习惯，以模块局部结果模型表达图片领域信息；不重构已有 PDF、表格或演示文稿模块。
- 首版输入为单张静态 PNG、JPEG 或 WebP。JPEG 的常见扩展名归一到同一格式；字节入口显式提供格式及非空来源，文件入口按后缀识别且允许显式格式覆盖。基于真实图像解码核对格式、尺寸及可读取性，不仅检查后缀。拒绝动画、多帧、损坏或与声明格式不符的输入，不静默取第一帧。
- 一次调用必须显式选择 OCR、图像描述或视觉理解，不默认连续执行三个任务。视觉理解要求非空问题，另外两类任务不接受问题参数，避免静默忽略。各任务使用独立、可追踪版本的提示词，实际图片均随本次任务发送。
- OCR 提示侧重忠实文字提取，保留可辨认的条件、否定、数字、单位和必要换行，不自行补写关系。图像描述侧重画面和主题概括。视觉理解依据原图与问题分析条件、箭头、图例及节点对应，不能只读取已有描述后作答，也不建立结果到再次推理的隐藏链路。
- 三个任务统一调用用户确定的阶跃星辰视觉 API，读取 STEP_API_KEY、STEP_BASE_URL、STEP_MODEL。约定模板地址为 https://api.stepfun.com/v1、候选模型为 step-5-preview，实际使用本地配置并核对账号可调用情况。凭据保留在被忽略的本地环境文件或运行时环境，不写入代码、测试样本、规格或公开事项。使用入口明确加载环境文件，核心模块接收已注入环境或显式配置，不隐式搜索文件。
- 拿到 API 信息后先核对官方图片输入、输出及错误契约，再实现一个最小客户端。只适配已选接口，不提前建设多提供方框架、自动回退、任务队列、自动重试或后台轮询平台。若该 API 需要异步处理，只按真实协议实现必要流程。
- 正常处理结果具有三种语义：有内容、未识别到文字、无法确认。未识别到文字仅表示本次 OCR 未得到可用文字，不证明图片中一定没有文字；无法确认用于不能支持问题所需关系的视觉理解，并保留可知内容与无法确认的原因。图像描述需要可用描述文本；无效或不符合约定的模型响应不冒充正常空结果。
- 成功表示正常完成所选任务，并不要求一定有非空正文。正常空 OCR 可返回空正文及明确状态；无法确认可返回不确定性说明与可知内容。读取、输入、配置、网络、鉴权、超时或协议失败时正文无值，错误独立返回，不暴露可误用为完整成功的部分派生正文。
- 所有正常模型产出均保留待核验事项，成功与待核验相互独立。机器可以记录模型明确给出的不确定性，不能宣称已自动检测全部幻觉；不提供自动纠错、内容保证或将模型自报置信度转成已核验事实的逻辑。人工确认、修订、停用及历史管理另行设计。
- 结果包含图片派生文字、任务和状态、实际输入来源、来源定位、图片尺寸及版本标识、处理模型和提示词版本、视觉理解的原始问题，以及独立待核验事项、警告和错误。提供方若只披露模型标识，则如实记录实际请求及响应披露的信息，未知模型修订不伪造为确定版本。
- 图片版本标识采用本次实际输入原始字节的 SHA-256；它区分字节版本，不将不同编码的相似画面判作同图。可选调用方原图标识与文档业务版本独立保留，不相互替代。相同图片字节在不同文档中出现时，文档来源仍保持区别。
- 可选原文档来源由调用方提供，包含文档标识、业务版本及有明确类型的实际位置。实际 PDF 页序、幻灯片序号等位置从 1 开始并保持类型区别，不从图片内容、文件名或模型猜出页号和版本；未知值为空，独立图片不要求父文档或页号。
- 整图结果定位到本次输入整图。处理调用方已经裁剪的图时，必须同时提供原图标识、原图宽高及原图中的裁剪矩形；采用原图左上为原点、像素单位、从 0 开始且右下边界不含的矩形坐标。入口校验完整性与范围，模型输出不能改写这组来源事实。首版只表达整张裁剪图与原图矩形的对应，不推算旋转／透视映射，不自动裁剪，不生成逐字或逐句区域。
- 图片身份、原文档位置及区域来源独立于正文存在，空 OCR、无法确认和调用失败仍可保留已知输入身份用于排查。输入失败时仅保留确已取得的来源事实，不为未成功解码的图伪造尺寸。若提供正文字符区间，沿用 Python 字符串左闭右开区间；空结果不伪造内容区间。
- 原图字节不被派生文字替代。模块不承担对象存储、文件持久化或来源 URL 托管；调用方负责保管可回查原图及其访问方式，内容摘要本身不是可打开的图片地址。
- 输入参数、图片数据和提供方响应分别在各自外部入口校验一次，内部传递确定类型，不反复防御。正常网络超时、鉴权拒绝、限流或服务失败返回独立诊断，避免凭据进入错误内容；不为假设性竞态或理论安全场景扩展架构。
- 本期不增加独立 Markdown 导出、数据库、HTTP 上传 API、格式总路由或统一切块交接能力。实现时提供模块使用说明与能力边界，保留已有测试和模块行为。

## Testing Decisions

- 用户已确认主要验收接缝为独立图片模块公开的文件／字节入口；两个入口属于同一业务边界。测试调用真实图像读取、提示组装、HTTP 客户端、响应解析和结果建立，不对内部辅助函数单独造测试接缝，也不对尚未实现的应用 HTTP 路由建立验收入口。
- 沿用 Python unittest 与固定本地样本。借鉴演示文稿测试的文件／字节等价、来源和待核验独立表达，以及 MinerU 测试的本地 HTTP 服务协议验证与显式真实 API 验收。尽量少用 mock，不在测试中复制图片处理或业务判断逻辑。
- 所有下载与构造样本集中保存到用户指定的测试样本目录。下载保持原始字节并记录来源、下载地址、日期、许可／署名、大小和 SHA-256；构造样本记录生成方式与固定预期。测试运行期间不下载、不随机重建输入，也不使用被测模型生成验收真值。
- 固定图片覆盖三种支持格式、可读文字、无可读文字、主题场景、清晰双分支审批图、模糊或截断关系、已经裁剪且带原图映射的图片，以及同名不同字节和相同图片关联不同原文档的来源情形。公开下载样本与为精确条件构造的样本分别注明；清晰审批图包含“金额超过 1 万元→负责人审批、其他情况→财务审批”的可见依据。
- 默认离线协议测试在公开入口连接本地 HTTP 服务，验证实际发送的图片、所选任务和视觉理解问题符合已选 API 契约，以及来源、任务状态、待核验和诊断的输出行为。服务返回可控内容用于验证客户端契约，不能用它证明模型真的读懂了图片。
- 默认测试覆盖文件／字节等价、格式识别与显式覆盖、损坏或不支持的图像、空来源／非法任务／缺失问题、裁剪元数据缺失或越界、实际字节摘要、来源原样保留、模型与提示词标识、正常空 OCR、无法确认及失败无正文。覆盖缺配置、鉴权拒绝、限流／服务错误、超时、无效响应，以及诊断与正文分离；无需穷举无现实依据的协议组合。
- 用户提供 API 并配置后，以显式开关运行真实服务验收，使用同一公开入口与固定图片。OCR 核对关键条件、否定、数字和单位；描述核对主题相关性及没有明显添造的业务规则；视觉理解分别检查两个审批分支，不能只检查一个正确审批人；模糊或截断图要求无法确认而非猜补关系。语义断言接受合理措辞，不依赖整段生成文字完全一致。
- 真实质量验收记录图片摘要、模型标识、提示词版本、实际输出、核验结论和局限，不记录凭据。API 不可用、验收跳过或只有离线服务测试通过时，不宣称真实视觉识别完成；验收发现错误时保留错误证据，修正提示或实现后重新验证受影响场景。
- 最后运行图片相关验收及仓库既有默认回归；真实云端验收保持显式启用，默认回归不自动消耗外部 API。代表图片通过不推广为任意流程图、版面或扫描质量均可靠。

## Out of Scope

- 从 PDF、Word、PPTX、HTML 或归档自动提取嵌图，及改造相邻模块的已有图片钩子。
- 矢量图片、动画／多帧、自动区域检测、自动裁剪、逐字框、复杂几何变换及通用版面还原。
- 图片 embedding、跨模态向量检索、最终切块、向量索引、召回、排序、完整 RAG 生成与多图问答。
- 原图存储服务、下载第三方图片 URL 的运行时功能、Web UI、摄取上传接口、数据库及后台任务系统。
- 多模型提供方抽象、OCR 与视觉 API 自动路由、MinerU PDF 客户端重构、模型训练或本地大模型部署。
- 人工审核／修订／停用结果的管理工作流、自动事实纠错及内容正确性保证。
- 将已有学习笔记的理解验收当作本仓库真实识图或多模态业务的实现证据。
