# 文本与网页类内容转换为格式化 Markdown

## Problem Statement

项目需要将已经取得的 TXT、Markdown、HTML、MHTML 和 JSON 内容转换为整篇、可检查、可交给后续处理的 Markdown 正文。当前相关模块仍为目录骨架，尚无转换实现、统一结果契约或可运行的转换测试。

不同载体存在不同的内容损失风险：错误解码会丢字或产生乱码；网页噪声可能淹没正文；MHTML 可能选错 HTML 部分；JSON 若只提取值，会丢失父路径与数组归属。仅凭结果非空或没有异常，不能证明取得了正确正文。

## Solution

在文本与网页类内容转换模块提供统一的公开转换入口，处理已有文件内容，输出整篇 Markdown、来源信息及独立的警告或失败原因，并支持将成功正文保存为 UTF-8 Markdown 文件。

网页默认采用正文提取，同时提供整页转换选项。图片处理仅预留空实现，待后续图片模块完成后接入。本期聚焦内容转换，不承担网页获取和最终检索切块。

## User Stories

1. As a 知识库开发者, I want 转换 TXT 文件, so that 纯文本能够进入统一的 Markdown 处理流程。
2. As a 知识库开发者, I want 规范化已有 Markdown, so that 复用其内容与结构而无需另建下游分支。
3. As a 知识库开发者, I want 转换静态 HTML, so that 页面中实际存在的文字可以成为 Markdown 正文。
4. As a 知识库开发者, I want 解包并转换 MHTML, so that 网页归档中的主 HTML 部分能够独立处理。
5. As a 知识库开发者, I want 转换合法 JSON, so that 结构化内容也能够统一交给后续流程。
6. As a 下游模块开发者, I want 每份输入得到整篇 Markdown 正文, so that 后续切块由共同入口负责。
7. As a 内容核验者, I want 保留标题层级, so that 章节内容仍有明确归属。
8. As a 内容核验者, I want 保留列表及其嵌套关系, so that 步骤和从属条件不会混淆。
9. As a 内容核验者, I want 保留普通表格的行列关系, so that 字段与对应数值不会脱离上下文。
10. As a 内容核验者, I want 保留代码块、必要缩进和代码中的空白, so that 格式整理不会改变代码含义。
11. As a 内容核验者, I want 保留正文中的文字链接及目标, so that 相关说明仍可追溯。
12. As a 知识库使用者, I want 默认获得网页文章主体, so that 导航、广告、页脚等附属内容减少对正文的干扰。
13. As a 知识库开发者, I want 选择整页转换, so that 正文提取不适用的页面仍有明确的转换方式。
14. As a 内容核验者, I want 脚本和样式内容不混入正文, so that 输出可供阅读和后续处理。
15. As a 知识库开发者, I want 静态页面没有可提取正文时得到明确失败, so that 脚本空壳不会被误认为有效知识。
16. As a 调用方, I want 指定已知编码, so that 可以基于明确来源纠正自动判断。
17. As a 调用方, I want 转换过程利用 BOM 和格式内编码声明, so that 解码优先采用有依据的信息。
18. As a 调用方, I want 在缺少明确编码依据时尝试 UTF-8 和编码探测, so that 常见文本仍有合理的解码途径。
19. As a 内容核验者, I want 解码失败时保留错误信息而非忽略字符, so that 关键条件不会在转换中悄悄丢失。
20. As a 内容核验者, I want 查看来源信息和采用的编码, so that 可以回查转换结果。
21. As a 调用方, I want MHTML 优先使用明确指定的主 HTML 部分, so that 已有归档线索得到尊重。
22. As a 调用方, I want 无明确主页面标识时使用确定的选择规则并收到警告, so that 可以核验自动选择是否符合目标。
23. As a 内容核验者, I want 知道实际选中的 MHTML 部分, so that 非空但缺少目标章节时可以定位问题。
24. As a 调用方, I want 无 HTML 或没有正文的归档明确失败, so that 附件不会被当成文字正文。
25. As a 内容核验者, I want JSON 保留对象、数组、值类型与嵌套关系, so that 每个值仍可解释其归属。
26. As a 调用方, I want 非法 JSON 得到明确失败原因, so that 无效结构不会伪装成转换成功。
27. As a 调用方, I want 成功正文可保存为 UTF-8 Markdown 文件, so that 可以直接查看并交给后续模块。
28. As a 下游模块开发者, I want 正文、警告和错误分别表达, so that 错误提示不会作为正文继续处理。
29. As a 图片模块开发者, I want 预留空的图片处理扩展点, so that 后续图片能力可以接入既有文字转换流程。
30. As a 测试维护者, I want 不同格式的测试输入统一保存在指定样本目录, so that 测试材料容易检查和复用。
31. As a 测试维护者, I want 下载的公开样本记录来源与完整性信息, so that 可以定位样本版本并复现验证。
32. As a 测试维护者, I want 通过公开入口运行真实转换实现, so that 验收覆盖实际使用行为。

## Implementation Decisions

- 实现范围为文本与网页类内容转换模块及其转换、导出公共接口；复用项目现有目录职责，不为此扩展上游路由、摄取 API 或其他格式模块。
- 输入为本地文件或调用方已经取得的文件字节，并提供识别格式、保留来源所需的信息。可指定编码与网页转换模式。本期不接受网址后自行抓取页面。
- 使用统一结果契约表达成功或失败：成功结果包含整篇 Markdown 正文、来源信息、采用的编码及警告；失败结果包含明确原因，不能提供可被误用为成功正文的错误字符串。字段和类型采用项目一致的简单表达。
- 提供保存成功正文的简单出口，写出 UTF-8 Markdown 文件。警告、失败原因等转换信息独立于正文，不自动拼入 Markdown。
- TXT 完成必要解码与段落保留；Markdown 完成必要规范化。统一换行、整理冗余空行等处理应保护标题、嵌套列表、普通表格、文字链接与代码块；不得对整篇内容直接合并空白而破坏结构。
- HTML 默认正文提取，并支持显式选择整页转换。清理脚本、样式等非正文内容；正文提取还需要排除可识别的导航、广告、页脚等噪声。保留正文已有的标题、列表、表格、代码与文字链接。整页转换改变筛选范围，不执行脚本。
- 编码依据按调用方指定编码、BOM、格式内编码声明、UTF-8、编码探测的顺序考虑；MHTML 的编码声明针对所处理的 HTML 部分。采用严格解码，不忽略错误字符。明确指定的编码解码失败应明确报告；缺少可用编码或探测无法提供可用结果时失败。自动探测不保证识别所有乱码。
- MHTML 完成 MIME 解包及 HTML 载荷解码；优先使用归档明确指定的主 HTML 部分。无明确标识时，选择解码后字符数最大的 HTML，并记录启发式选择警告及选中来源。该规则不保证符合用户目标，不声称最大即正确。没有 HTML 或选中内容最终没有正文时失败。
- JSON 去除必要的 UTF-8 BOM 后解析、校验，保留原有对象、数组及值类型，将格式化 JSON 组织在 Markdown 的 JSON 代码围栏内。保留层级与数组顺序；不改写为自然语言，不转换为数字键对象，不做长度预分组。
- 图片处理仅预留空实现（pass），待后续图片处理模块完成后接入。本期不实现图片引用整理、Base64 图片处理、归档附件导出、下载、存储、OCR 或图片相关转换警告，也不把这些能力设为验收条件。空实现不能中断正常文字流程或将正文替换为空值。
- 读取失败、解码失败、非法 JSON、无可提取正文等情况明确失败；可继续完成文字转换且存在已知问题时，警告单独记录。不得以原 HTML 或错误文字冒充成功的 Markdown 正文。
- 外部输入在公共入口完成必要校验，内部不重复检查已确定的类型。按现有项目流程实现；保持主流程清楚，不提前建立仅为假想扩展服务的通用框架。

## Testing Decisions

- 用户已确认以本模块公开转换、导出入口作为主要行为测试边界。测试调用真实解析和转换实现，观察返回结果与实际导出文件，尽量少用 mock；不复制转换算法到测试中，不绑定内部辅助方法或调用次数。
- 当前仓库没有可复用的已实现转换测试、fixture 规范或测试命令先例。沿用现有测试目录组织，以 Python 环境可直接运行的方式验证，不额外建设测试平台。
- 所有用于验证的 TXT、Markdown、HTML、MHTML、JSON 输入，以及后续补充的编码变体、失败和结构边界样本，均保存于用户指定的[测试样本目录](/E:/aaa-project/rag-me/tests/testFile)。不把同类输入分散到其他目录，也不只内嵌在测试代码字符串中。
- 当前已下载六个公开文件，覆盖五类格式：Project Gutenberg 的 UTF-8 长文本；Python Packaging Authority 的项目 Markdown；Python 官方教程 HTML；JSON Schema 的嵌套 JSON；Chromium 的单页面与多 HTML 部分 MHTML。来源说明和机器可读的来源、大小、SHA-256 记录与样本保存在同一目录。
- 公开样本来源：[UTF-8 长文本](https://www.gutenberg.org/ebooks/11)、[项目 Markdown](https://github.com/pypa/sampleproject/blob/main/README.md)、[Python 教程 HTML](https://docs.python.org/3.11/tutorial/datastructures.html)、[嵌套 JSON](https://json-schema.org/draft/2020-12/schema)、[单页面 MHTML](https://github.com/chromium/chromium/blob/main/third_party/blink/web_tests/mhtml/simple_page_unmht.mht)、[多部分 MHTML](https://github.com/chromium/chromium/blob/main/third_party/blink/web_tests/mhtml/multi_frames_contentid.mht)。
- 已下载样本保持原始字节。测试使用固定本地副本，运行验收无需访问下载站点；更新样本时同步来源与摘要。
- TXT 验证已知事实和段落保留；Markdown 验证标题、列表、代码及文字链接；HTML 验证主体标题、正文与代码保留，以及正文提取和整页转换的行为差异。普通表格与导航、广告清理使用明确可核对的样本，必要时在统一样本目录补充。
- MHTML 验证解包、字符集解码、主页面标识优先、无标识时按解码字符数选择、来源记录及启发式警告。多部分样本只依据既定选择规则验收，不要求合并所有框架，不把自动选择等同于正确识别业务目标。明确主页面标识与无 HTML 的边界可用补充样本覆盖。
- JSON 验证围栏中的内容可重新解析，值、类型、数组顺序及嵌套结构与输入一致；不会生成最终 chunk 或执行长度截断。另覆盖 BOM 和非法 JSON。
- 编码验证覆盖显式编码、BOM、HTML/MIME 声明、UTF-8、可探测的其他编码及明确失败；用已知中文事实检查关键文字没有丢失，不只断言返回非空。
- 失败验证覆盖读取失败、编码失败、非法 JSON、脚本空页面、无 HTML 归档及无正文；错误信息不成为正文，失败不导出伪装成成功的正文文件。
- 导出验证检查 UTF-8 编码、正文与转换结果一致，以及来源、警告、错误未混入文件。图片部分只检查空扩展点不会阻断文字转换，不验收任何图片处理效果。
- 当前阶段仅完成规格和样本准备、样本格式与完整性核对；模块实现后再运行本节描述的转换验收，不将下载成功描述为转换通过。

## Out of Scope

- URL 下载、爬虫、登录态处理、浏览器执行 JavaScript、接口补取动态内容；这些能力以后是否实现另行决定。
- 图片处理本身及其效果验证；本期仅保留空扩展点。
- 最终文档切块、长度和 token 预算、重叠、父子块、embedding、数据库、索引、检索及问答效果。
- PDF、Word、表格文件、办公格式、音视频、ZIP 等其他载体的转换。
- JSON 结构预分组、数组转数字键对象、对参考项目策略的逐项复制，以及原始格式或坐标的无损还原承诺。
- 合并 MHTML 中所有子页面或执行其中的脚本；保证任意网页均能完美识别文章正文。
- 实现尚为空的整套摄取 API、格式路由、存储、队列或批处理平台。
