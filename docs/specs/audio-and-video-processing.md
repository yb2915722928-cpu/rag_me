# 音视频处理：API 转写、视频理解与片段级来源追溯

> 已发布：[GitHub Issue #33](https://github.com/yb2915722928-cpu/rag_me/issues/33)，标签：enhancement、ready-for-agent。用户已确认本轮继续实现及验证。

## Problem Statement

用户希望把音视频处理笔记中的知识落实到项目，让本地录音和视频产生可供后续 RAG 使用、能够回听回看的媒体派生文字。当前音视频处理模块只有空初始化文件，尚无媒体读取、转写、视频理解、时间定位或相应验收。

转写可能丢失金额、否定、问答语境与说话人；仅有文字不能解释“右侧分支”或演示操作。文字若没有关联同一版本原媒体及真实处理范围，后续无法核验。用户电脑配置不高，因此模型计算优先使用现有阶跃星辰 API，本机只进行必要媒体准备。

## Solution

在独立音视频处理模块提供公开文件入口和字节入口。音频通过阶跃 ASR API 转写；视频明确选择仅转写、仅画面理解或同时处理，画面使用阶跃原生视频理解 API。本地只探测媒体、提取音轨、切片及必要封装，不部署本地语音或视觉模型。

输出按原时间顺序排列的媒体派生文字及结构化片段。每个片段保留原媒体来源、媒体版本标识、实际起止时间、内容来自语音还是画面，以及独立的待核验事项和诊断。首版时间粒度为真实处理片段，不提供逐句或逐词对齐；说话人保持未知，不从文字猜真实身份。

## User Stories

1. As a 知识库开发者, I want 处理本地音频文件, so that 录音内容能够转为后续可用文字。
2. As a 知识库开发者, I want 处理本地视频文件, so that 视频中的语音和画面能够按需取得文字表示。
3. As a 调用方, I want 通过字节入口提交已经取得的媒体, so that 不必在模块之外另建文件处理流程。
4. As a 调用方, I want 文件和字节入口遵守同一结果契约, so that 来源相同时能核验相同处理行为。
5. As a 低配置电脑用户, I want 语音识别在云端 API 执行, so that 不必下载或运行本地 ASR 模型。
6. As a 低配置电脑用户, I want 视频理解在云端 API 执行, so that 不必运行本地视觉模型。
7. As a 调用方, I want 复用已有阶跃凭据, so that 不必为本功能重新接入其他供应商。
8. As a 调用方, I want 分别配置 ASR 与视觉模型, so that 图片模型名称不会被错误地用于语音转写。
9. As a 调用方, I want 核心模块接收显式配置或运行时环境, so that 环境文件加载位置清楚可控。
10. As a 本地使用者, I want 命令行入口明确加载指定环境文件, so that 能直接运行示例并查看结构化结果。
11. As a 视频使用者, I want 只转写音轨, so that 仅关心说过什么时不额外调用视频理解。
12. As a 视频使用者, I want 只理解画面, so that 静音演示或幻灯片也能够处理。
13. As a 视频使用者, I want 同时处理语音和画面, so that 能分别核验说法与画面关系。
14. As a 内容核验者, I want 区分语音转写与画面派生文字, so that 生成的画面解释不会冒充原话。
15. As a 调用方, I want 为视频理解提供具体问题, so that 可以检查条件、箭头及节点对应关系。
16. As a 调用方, I want 没有具体问题时获得画面内容概括, so that 视频可以产生主题线索。
17. As a 内容核验者, I want 金额、否定和问句语境保留在转写中, so that 学员的疑问不会被改写为制度结论。
18. As a 内容核验者, I want 无依据的说话人保持未知, so that 系统不会凭文字猜测讲师或学员身份。
19. As a 内容核验者, I want 知道当前不提供自动说话人区分, so that 不会把未知标签误当能力已实现。
20. As a 调用方, I want 长媒体逐片串行调用 API, so that 本机不会同时装载或提交全部切片。
21. As a 调用方, I want 调整处理片段时长, so that 可以按内容和服务限制选择定位粒度。
22. As a 内容核验者, I want 每段关联真实处理范围, so that 能回到原媒体核验条件及前后语境。
23. As a 内容核验者, I want 时间从原媒体起点计算并统一使用明确单位, so that 剪辑后的局部时间不会误指原文件。
24. As a 内容核验者, I want 片段级时间和逐句时间明确区别, so that 定位精度不会被夸大。
25. As a 内容核验者, I want 复制视频流时记录实际切片边界, so that 关键帧切片偏移不会被隐藏。
26. As a 调用方, I want 保留本次实际输入的媒体版本标识, so that 同名不同文件的结果不会混用。
27. As a 调用方, I want 可选传入业务媒体标识和版本, so that 已知业务来源可与字节摘要并存。
28. As a 内容核验者, I want 未知业务版本保持未知, so that 文件名不会被当成版本事实。
29. As a 内容核验者, I want 画面关系不清晰时保留不确定性, so that 系统不会猜补审批人或操作条件。
30. As a 内容核验者, I want 所有模型产出保持待核验, so that 调用完成不被解释为内容已经正确。
31. As a 调用方, I want 正常空转写与服务失败区分, so that 本次没有得到语音文字不会被误判为接口故障。
32. As a 调用方, I want 仅画面模式允许无音轨视频, so that 静音素材不必伪造语音。
33. As a 调用方, I want 请求转写但没有音轨时明确失败, so that 不会得到冒充成功的空音轨结果。
34. As a 调用方, I want 文件损坏、格式不支持和工具缺失得到独立诊断, so that 可以定位媒体准备失败。
35. As a 调用方, I want 鉴权、限流、超时和无效响应得到可识别错误, so that 可以决定补配置或重新调用。
36. As a 下游开发者, I want 处理中途失败时不收到冒充完整成功的正文, so that 不完整内容不会直接进入后续流程。
37. As a 下游开发者, I want 正文、来源、待核验事项、警告和错误分别表达, so that 诊断不会混入知识内容。
38. As a 项目维护者, I want 凭据不进入日志、样本或事项, so that 运行配置继续保留在本地环境。
39. As a 测试维护者, I want 固定媒体样本记录来源和摘要, so that 验收能够重现。
40. As a 测试维护者, I want 从公开入口验证真实媒体准备与客户端协议, so that 内部辅助函数的变化不会破坏测试目的。
41. As a 内容核验者, I want 另行使用短小固定样本核验真实 API 结果, so that 固定 HTTP 响应不会被当成真实识别能力证明。
42. As a 下游开发者, I want 独立取得处理结果, so that 切块、入库、索引和问答可以由后续模块承担。

## Implementation Decisions

- 实现集中在独立音视频处理模块，提供文件与字节公共入口、模块局部结果模型、阶跃客户端和命令行示例；沿用相邻模块的调用习惯，不建设应用 HTTP 上传路由或统一摄取框架。
- 首版支持 WAV、MP3、M4A、OGG、FLAC 音频和 MP4、MOV、MKV 视频。文件入口按后缀识别并允许显式格式覆盖；字节入口显式提供格式与非空来源。FFprobe 检查实际容器、媒体流与可用时长，无法处理的编码给出明确错误，不以改后缀假装支持。
- 明确选择转写、视频理解或两者；音频只允许转写。视频理解可携带非空问题，没有问题则概括画面；纯转写不接受问题，避免静默忽略。选择仅画面时不调用 ASR，选择仅转写时不调用视觉 API。
- 模型计算全部走 API。本地 FFmpeg/FFprobe 只承担探测、音轨提取、必要重采样、切片与封装。视频优先复制码流，不默认做全视频重编码；无法直接封装成服务支持的 MP4 时明确说明需要调用方预先转码。
- ASR 采用同步文件转写接口，上传由原音轨取得的单声道、16 kHz、16 bit PCM WAV。使用独立 ASR 模型配置，默认选择官方同步接口支持的 stepaudio-2.5-asr，不把视觉模型配置自动用于 ASR。
- 视频画面使用原生视频输入，按实际处理片段传入内联视频内容，读取现有视觉模型配置。以画面信息为任务目标；视频接口即使能够感知声音，也不能用其生成内容冒充忠实 ASR 原话。
- 复用 STEP_API_KEY 与 STEP_BASE_URL；视觉使用 STEP_MODEL，语音增加 STEP_ASR_MODEL，并允许显式配置覆盖。CLI 明确加载指定环境文件且不覆盖已有进程变量；核心不隐式搜索环境文件。示例只记录变量名和非秘密默认值，不修改已有凭据。
- 音轨默认按 30 秒、视频画面默认按 60 秒处理，时长可配置。按时间顺序逐片串行请求，使用临时文件并在完成后清理；文件入口不为计算摘要而一次载入整个长媒体，字节入口只对调用方已提供的字节承担同等处理。
- 视频复制码流切片可能受关键帧影响，记录 FFmpeg 实际切片清单中的时间范围，不按目标时长虚构均匀边界。音轨定位同样对应实际提取范围。中间媒体保留原时间偏移；非零容器起点归一到用户播放文件的起点。
- 每次提交满足提供方大小限制。超过限制时返回可识别诊断并说明调整片段长度，不增加对象存储、自动公网托管、后台任务或隐藏的昂贵视频压缩流程。
- 时间单位统一为从原媒体播放起点计算的秒，范围采用左闭右开且末段止于实际结束。每段明确标记片段级定位；不由字数平均分配逐句时间，不把模型生成的时间当作可靠字词时间戳。
- 首版说话人字段为未知，并给出能力边界说明。同步接口没有提供说话人依据，既不根据问句猜人，也不将“讲师／学员”写成已识别身份。匿名说话人区分及其任务内稳定性不属于本次承诺。
- 来源包含输入位置、本次原始字节的 SHA-256、真实媒体类型及可取得的时长；调用方可提供业务媒体标识与版本，未知信息为空。内容摘要区分字节版本，不代替可打开的原文件位置或业务版本。
- 结果保留按原时间排列的片段列表，每段具有语音／画面类型、起止时间、派生文字、任务状态和实际处理模型信息。完整文字按时间及类型明确组织，不自动把提问与回答改写为业务规则，不将画面解释与语音揉成无法追溯的总结。
- 视频提示要求保留可见条件、否定、箭头与节点对应；针对问题无法确认时明确给出可知信息及原因，不猜补身份、关系或不存在的操作。使用可跟踪提示词版本；不声称已经自动发现所有幻觉或帧采样损失。
- 所有正常模型输出保留待核验事项，包括空转写及无法确认；时间定位、模型置信度或成功状态都不能清除待核验。正常空转写只表示本次未取得可用语音文字，不证明整份录音不存在语音。
- 无音轨视频可完成仅画面任务；请求转写或同时处理时缺少音轨明确失败。首版选择第一个可用音轨，不自动合并多语言或多声道独立发言；结果记录所选音轨。
- 失败保留已取得的输入来源及独立错误，不返回可被误当成完整成功的正文或片段。错误可记录失败阶段和片段位置；不实现断点续传或部分成功入库。可解释的正常空转写与模型明确无法确认属于正常状态。
- 读取、输入选项、工具输出和 API 响应在各自入口校验一次。真实的缺工具、损坏媒体、缺配置、鉴权、限流、超时、HTTP 错误和无效响应有明确诊断；不额外构建多提供方路由、通用重试或理论竞态防护。

## Testing Decisions

- 用户已确认主要验收接缝为本模块公开文件／字节入口，两个入口属于一个业务边界，同时进行少量真实 API 验收。
- 测试检查外部可观察行为：媒体派生文字、语音与画面归属、实际原时间范围、来源版本、待核验事项、诊断及退出结果。不测试内部函数调用次数，不在测试中复制媒体处理算法。
- 沿用仓库的 Python unittest 和固定本地样本。参考演示文稿的文件／字节契约，以及图片模块的本地 HTTP 协议验证和显式真实 API 验收，不引入新的测试平台。
- 所有媒体、预期说明及来源摘要集中到现有测试样本目录；记录公开来源与许可或本地构造方式、大小和 SHA-256。测试期间不下载或随机重建样本；合成语音若用于构造样本，明确标注合成来源，不冒充真实讲师录音。
- 固定样本覆盖短音频、含语音与双分支审批画面的视频、无音轨视频、静音音轨、跨多个切片的媒体、非零时间起点及损坏文件。语义真值由已知原稿和画面建立，不使用被测模型自己的输出作为答案。
- 默认测试调用真实 FFmpeg/FFprobe 和真实 HTTP 客户端，服务端由本地 HTTP 夹具返回可控结果。检查实际 multipart 音频、视频输入、所选模型及问题，验证协议而不宣称真实 ASR 或视频理解质量。
- 检查文件／字节入口在相同来源及固定响应下等价，SHA-256 对应原媒体而非转码结果，语音与画面类型不混淆，正常空转写与失败区分，未知说话人不被补成角色。
- 用多个真实切片核验顺序、总时长、原时间偏移和实际切片边界，不只比较目标时长。视频切片可重新探测或播放，对照固定画面内容检查没有把后段文字定位到前段。
- 失败检查包括格式不支持、损坏输入、缺少所需音轨、缺配置、鉴权、限流、超时、无效响应及中途片段失败。失败无可误用为完整成功的正文，已知来源不丢失；不穷举没有实际依据的异常组合。
- 真实 API 验收通过显式开关执行，使用少量短小固定样本。转写核验金额、单位、否定及问句上下文；视频分别核验超过一万元与其他情况对应的两个审批分支，并观察不清晰画面的不确定性。不能只断言输出非空。
- 真实运行记录输入摘要、请求模型、实际响应、时间范围、核验结果和局限，不记录凭据。接口不可用或质量检查失败如实说明，不以跳过测试替代验收成功，不把有限样本通过扩大为任意媒体均准确。
- 本模块验证止于媒体准备、云端调用、结果与来源关系，不代表切块、索引、召回、生成及答案引用的完整 RAG 链路已经成立。

## Out of Scope

- 本地 ASR、视觉或说话人模型部署，GPU 推理、模型训练与微调。
- 逐句／逐词强制对齐、自动说话人区分、实名识别、人工身份对应管理及跨媒体身份保持。
- 为异步 ASR 自动公网托管本地文件、对象存储、上传服务、后台任务与轮询平台。
- 实时麦克风或摄像头输入、流式直播、实时字幕、字幕编辑及独立字幕格式导出。
- 抽帧与原生视频两条路线同时建设，复杂动作无损还原、自动检查全部幻觉或保证任意内容准确。
- 视频自动重编码优化、批量并发、任务恢复、多供应商切换和自动重试平台。
- 上游上传 API、网页下载、格式总路由、数据库、原媒体存储和统一切块交接模块建设。
- 最终检索切块、embedding、向量检索、完整 RAG 问答、引用播放器和前端页面。
