# 读取 CSV 与 XLSX，并保留面向 RAG 的表格对应关系和上下文

## Problem Statement

知识库开发者需要处理真实 CSV 和 XLSX 文件，让后续 RAG 能明确知道每个值属于哪一行、哪一列，使用什么单位，适用于哪个版本和对象，并能回查原文件。将单元格直接拼接成文字会丢失这些关系；只取得单行，也不保证足以回答跨行比较问题。

目前独立表格文件处理模块只有占位内容。已有文本、网页、PDF 与 Word 解析建立了公开文件／字节入口和正文、来源、诊断分离的约定，但没有真实 CSV／XLSX 读取、多层表头、表格共同上下文、按行表示或单元格来源的独立契约。

学习笔记已说明按行表示、整表表示及证据覆盖的取舍，但历史实验仅使用已提取单元格和人为固定的证据范围，不能替代本项目的真实文件解析验收。

## Solution

在独立表格文件处理模块中读取 CSV 和 XLSX，保留表格对应关系、完整列名、单位、表格共同上下文和来源信息，同时提供调用方显式选择的按行表示与整表 Markdown 表示。

简单表采用明确默认规则；复杂布局通过工作表、区域和表头行配置处理。普通空白、数字零、公式文本与公式缓存结果保持区别。下游可以独立取得某一行及其上下文，也可以取得完整小表；本模块不据此宣称已经完成索引、召回或模型问答。

## User Stories

1. As a 知识库开发者, I want 读取真实 CSV 文件, so that 已有文本表格可以进入文档解析流程。
2. As a 知识库开发者, I want 读取真实 XLSX 文件, so that 工作簿内容可以成为可核验的 RAG 输入。
3. As a 调用方, I want 使用文件或字节入口, so that 本地文件与已取得的上传内容采用同一行为契约。
4. As a 调用方, I want 显式选择按行表示或整表表示, so that 可以根据问题需要选择证据粒度。
5. As a 下游开发者, I want 独立取得一条行记录及其完整列名, so that 行离开原表后仍能解释各个值。
6. As a 内容核验者, I want 单元格保持原始行列归属, so that 北京的住宿标准不会被误配到上海或餐补字段。
7. As a 内容核验者, I want 列名保留单位, so that 500 元／晚不会与 100 元／天混用。
8. As a 调用方, I want 指定多层表头行, so that 上下层名称可以展开为完整列名。
9. As a 内容核验者, I want 合并标签只在确有合并记录的范围内补齐, so that 普通空白不会被擅自解释为上一条记录的值。
10. As a 调用方, I want 按工作簿顺序处理非空可见工作表, so that 简单多表工作簿有确定的默认行为。
11. As a 调用方, I want 显式选择工作表与矩形区域, so that 可以处理带说明行或多块内容的工作表中的目标表格。
12. As a 调用方, I want 为每张表提供表名、版本、适用条件与解释性备注, so that 数字的业务含义不会丢失。
13. As a 下游开发者, I want 两种表示都携带表格共同上下文, so that 取得单行与完整表时采用相同解释条件。
14. As a 内容核验者, I want 未提供的上下文明确保持未知, so that 文件名或其他猜测不会冒充业务事实。
15. As a 内容核验者, I want 来源指向真实文件、工作表和原始行列, so that 可以回查数据及表头。
16. As a 内容核验者, I want CSV 的字段内换行不破坏来源位置, so that 可以找到对应原始记录和物理文本行。
17. As a 调用方, I want 显式指定 CSV 编码与分隔符, so that 已知文件约定可以得到尊重。
18. As a 内容核验者, I want CSV 保留标准引号、字段内逗号和换行, so that 文字内容不会被拆成错误的列或记录。
19. As a 内容核验者, I want CSV 字段保留原始文本和前导零, so that 编号 00123 不会变成 123。
20. As a 内容核验者, I want 普通空白与数字零保持区别, so that 未知或不适用的值不会伪装成零。
21. As a 内容核验者, I want 同时查看公式文本与已有公式缓存结果, so that 可以区分表达式和文件中保存的数值。
22. As a 调用方, I want 公式无缓存时得到结果未知的表达与独立警告, so that 不会将表达式误当作已计算结果。
23. As a 内容核验者, I want 百分比、日期和常见金额格式保留含义, so that 20% 不会被无说明地表示为 0.2。
24. As a 下游开发者, I want 保留 XLSX 原值、类型和原始数字格式, so that 常见显示文本之外仍有可核验的数据。
25. As a 调用方, I want 无法可靠解释的自定义格式得到独立提示, so that 不会把近似显示当作完整 Excel 显示还原。
26. As a 内容核验者, I want Markdown 中的管道符、反斜杠和单元格换行保持字段归属, so that 输出排版不会改变表格对应关系。
27. As a 调用方, I want 行宽不一致、空表头与重复完整列名明确失败, so that 字段不会静默错位或被覆盖。
28. As a 调用方, I want 损坏文件、非法配置和找不到的工作表提供明确错误, so that 无效结果不会继续进入后续流程。
29. As a 下游开发者, I want 正文、结构化表格、来源、警告和错误分别返回, so that 诊断不会作为知识正文处理。
30. As a 调用方, I want 选中表无法解析时整次转换失败, so that 不会把缺表的部分输出误当作完整文件。
31. As a 内容核验者, I want 比较北京单行、完整小表和北京加上海两行的证据覆盖, so that 可以解释单行缺证据与表示错误的区别。
32. As a 内容核验者, I want 不同版本或适用条件在输出中保持可见, so that 数值齐全也不会掩盖业务条件不匹配。
33. As a 测试维护者, I want 所有下载与构造样本集中保存, so that 测试输入可以直接检查、回查与复用。
34. As a 测试维护者, I want 下载样本记录来源、大小及摘要, so that 能核对固定样本版本。
35. As a 测试维护者, I want 通过公开入口运行真实 CSV／XLSX 解析, so that 验收覆盖实际调用行为。
36. As a 测试维护者, I want 默认验收无需联网或语言模型, so that 可以稳定复现文件解析与表示结果。

## Implementation Decisions

- 业务实现集中在用户指定的独立表格文件处理模块。支持 CSV、XLSX；不接管已有 HTML、PDF、Word 中的表格提取，也不新增摄取 HTTP API、格式总路由或通用解析框架。
- 沿用公开文件转换入口和字节转换入口的调用习惯：文件入口按扩展名识别，可显式指定格式；字节入口显式提供格式与来源。允许传入表示模式、CSV 编码／分隔符、XLSX 工作表选择，以及每张表的区域、表头行和共同上下文。具体参数与类型用简单、明确的模块局部模型表达，不重构现有模块的结果类型。
- 返回转换结果，包含成功正文、输入来源、结构化表格／行／单元格、表格共同上下文、来源位置、采用的 CSV 编码，以及独立警告与错误。结构化数据是本次真实解析的结果，不从输出正文反向猜测。两种模式读取同一表格内容，区别是正文的组织方式。
- 按行模式允许独立取得每条行记录的文本、完整列名、共同上下文及来源，不要求下游再从整篇字符串切出记录。整表模式按工作表顺序组织表头与数据，提供带上下文的 Markdown 表。结构化行不是最终 chunk，也不包含检索 ID、embedding 或自动预算决策。
- CSV 使用标准 CSV 读取能力，默认逗号分隔，第一条非空记录为单行表头；允许显式指定分隔符、编码和表头记录位置。采用既有严格解码规则：显式编码、BOM、UTF-8、必要时编码探测；不得忽略坏字符。编码探测警告独立保留。字段保持文本，不自动推断数字、日期或公式；以等号开头的 CSV 文本仍是文本。
- XLSX 使用能够读取工作表、合并范围、原始值、公式与缓存的现有成熟库；优先采用 openpyxl，在实施时声明并验证依赖。CSV 不因此引入 pandas，公式不引入计算引擎，也不自行实现完整电子表格文件解析器。
- XLSX 默认按工作簿顺序处理有内容的可见工作表，一张工作表默认视为一张矩形表；默认使用所选区域第一条非空行为单层表头。允许显式选择工作表（包括明确指定的隐藏表）、矩形区域及连续的多层表头行，位置均基于原始工作表且从 1 开始。默认跳过空表和隐藏表，不把跳过的内容宣称为已解析正文；全部为空或选区无数据记录时明确失败。显式选择的表无法解析时，不静默跳过。
- 多层表头沿真实列归属展开为完整列名，原有单位不得丢失。表头中的合并标签只按实际合并范围传播；数据区的合并共同标签保留其锚点与覆盖关系，不把任意普通空白当作合并，也不把合并数值复制为多条独立测量值。选区切断必要合并关系或结构不能明确表示时给出可定位错误，要求调用方修正区域，不自动猜布局。
- 表格共同上下文由调用方按表提供：表名、版本、适用条件及解释性备注。不得从文件名、邻近文字或工作表名猜出版本与适用对象；工作表名只作为可靠来源事实。关键上下文缺失时保持未知并单独提示，不阻止其他可解释字段的解析；备注未提供时不制造备注。相同上下文可以共享存储，但独立取得某行时必须一起提供。
- XLSX 普通空白保持空白；数字零、布尔值、文本等保留原始类型。CSV 空字段保持空文本语义，不转成数字零。跳过纯空记录时仍保留其他记录在原文件中的位置，不将剩余记录重编号为原始行号。
- XLSX 公式保留表达式和文件保存的缓存结果；无缓存时明确结果未知并单独警告，不伪造数值，也不执行公式。已有缓存标记为缓存而非最新计算结果。单元格错误值同样不能冒充普通数值。
- XLSX 保留原值、原始类型和数字格式。支持明确的常见整数／小数、百分比、金额及日期／时间显示；例如百分比格式的 0.2 显示为 20%，日期使用无歧义文本。首版只覆盖经固定样本验收的常见格式，不实现任意自定义数字格式解释器；未支持格式保留原值与格式并提示，不猜测单位、倍率或含义。
- 来源分为输入文件、表、行和单元格的实际位置。XLSX 包含工作表名、原始行列／单元格坐标及必要合并锚点；CSV 包含原始记录和字段位置，字段内换行时同时保留物理文本行范围，明确区分记录序号与物理行号。来源不标成 PDF 页序、Word 页码或向量索引位置。
- 整表 Markdown 对管道符、反斜杠和单元格内换行做与现有行为相容的表示，保持列数与值的归属；文本序列化不能改变结构化原值。业务上下文可在正文中表达，通用警告和错误不能混进正文。
- 行宽不一致、最终完整列名为空或重复、非法选区／表头配置、找不到的工作表、损坏文件或读取失败返回明确错误。外部输入在公开入口校验一次，内部不反复校验确定类型。选中表有解析失败时整次失败，正文为无值，不暴露可误用为完整成功的部分表／行。
- 本期不新增 Markdown 文件导出能力。调用方使用返回的正文和结构化结果；不为本功能重构已有导出接口。

## Testing Decisions

- 用户已确认以独立表格模块的公开转换入口为主要验收接缝：固定真实 CSV／XLSX 输入，运行真实读取、规范化和表示实现，检查正文、结构化行列、来源及诊断。以字节入口覆盖主要行为，文件入口验证后缀识别、读取错误以及与字节入口的等价性；不增加内部辅助方法测试接缝，也不为尚为空的 HTTP 路由建立新接缝。
- 沿用仓库的 Python unittest、固定本地样本及现有测试命令。借鉴文本网页测试的文件／字节入口与编码验收、HTML／DOCX 测试的字段对应关系和特殊字符验收，以及 PDF 测试的整次失败约定。测试只观察外部行为，不复制业务解析或格式化逻辑，不绑定辅助函数调用次数；尽量不使用 mock。
- 所有下载和构造输入统一保存在用户指定的[测试样本目录](/E:/aaa-project/rag-me/tests/testFile)。公开输入保持原始字节并记录来源、大小与 SHA-256；补充样本记录构造方法、固定预期和构造脚本。测试运行时不下载或重建样本，不使用被测模块生成期望结果。
- 已下载 seaborn 的 Iris CSV 和 pandas 的 XLSX 测试工作簿，并核验 Git blob SHA、文件大小和 SHA-256；CSV 已核对首行记录和 150 条数据，XLSX 已核对 ZIP 完整性和四个工作表。该工作簿含空表头与仅表头工作表，验收普通矩形表时应显式选取有效工作表／区域；也可用于确认默认规则下的明确失败。它不替代中文、多层表头、合并与公式的专门样本。
- 实施时构造真实 CSV 与 XLSX 的教学差旅表，表名“员工国内差旅标准”、版本“2026示例版”、适用“普通员工，国内出差”，住宿上限北京 500 元／晚、上海 450 元／晚、杭州 400 元／晚，餐补北京和上海 100 元／天、杭州 80 元／天。断言实际字段与城市的配对、单位、共同上下文与原始来源；不能只断言所有词语都出现。
- 从真实解析结果固定选择三组证据：只提供北京行时输出不含上海；完整小表及北京加上海两行均包含两个住宿值和一致上下文。验收可用固定期望确认两组数值相差 50 元／晚，但不在生产解析器实现问答或减法；不得通过读取整张结构化表暗中补齐“只提供北京”的证据，也不建设只适用于样例的文本反解析器。缺少上海的结论来自所提供证据范围，不推导为按行策略整体效果差。
- 验证多层表头及明确合并范围：表头的父子名称和单位正确展开；数据区的共同标签只覆盖合并范围，范围外的真实空白仍为空白；原始单元格与合并锚点可回查。非法或切断关系的配置不能以猜测继续成功。
- 验证工作表顺序、默认可见表、显式选表／选区／表头行，隐藏与空表的既定处理；跳过空行后来源仍为原始位置。任一选中表失败时不返回部分成功正文。
- CSV 覆盖 UTF-8、BOM、显式其他编码、实际可用的编码探测与严格解码失败；覆盖逗号／显式分隔符、带引号逗号、转义引号、字段内换行、前导零及以等号开头的普通文本。字段内换行时验证记录与物理行范围；行宽不一致、坏引号及无效／重复表头有明确错误。
- XLSX 覆盖真实空白与数值零、布尔值、文本、普通数值、日期、百分比、常见金额，以及未知自定义格式的保留与提示。验证真实值与显示含义，不仅比较整体字符串快照。
- 公式样本分别覆盖有缓存和无缓存。构造方式明确区分人为预设缓存与真实办公软件重算结果；即使有固定缓存，也只证明能读取保存值。验证表达式、缓存标记、空缓存警告和原始坐标，不以公式重算结果作为本模块能力。
- 覆盖上下文完整、版本／对象未知、不同表上下文不同的场景，确保已知值原样保留、未知项不伪造、每条独立行记录仍能取得相应上下文。此处验证信息保留，不新增通用业务问题适用性判定器。
- 覆盖 Markdown 管道符、反斜杠和字段内换行的结构保留，以及不存在文件、损坏 XLSX、非法配置、不支持格式、空文件／仅表头／无数据表的失败。警告与错误始终独立于正文。
- 功能实施后运行新增行为测试及仓库现有默认测试，确认文本、网页、PDF 与 Word 的既有行为没有回归。当前阶段的样本核对不计作功能测试通过。

## Out of Scope

- 旧版 XLS、XLSM 宏、ODS、图表／图片识别，以及 PDF／Word／HTML 表格提取或跨文档接管。
- 任意一页多表自动定位、自动猜表头、自动抽取表外版本／适用条件、跨页表格拼接和任意复杂布局恢复。
- 公式执行或重算、保证缓存为最新值、外部工作簿计算、完整 Excel 数字格式与视觉样式还原。
- 自动选择按行或整表策略、按问题选行、上下文预算、最终 chunk 切分、表格保护切块、父子块及检索 ID。
- 向量化、索引、数据库、召回、重排、语言模型问答、SQL 分析、大表精确聚合，以及通用问题证据完整性／适用性判定器。
- HTTP 摄取接口、总格式路由、文件存储服务、任务队列、网址下载能力和批处理平台。
- 本模块新增导出服务，或以学习示例推导真实检索质量、性能提升及已部署结果。
