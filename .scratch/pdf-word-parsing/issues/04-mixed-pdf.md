# 04：逐页解析混合 PDF 并合并正文与来源

**计划标签：** enhancement、ready-for-agent

## Parent

Part of [#8：实现 PDF 与 DOCX 解析并保留正文关系和来源](https://github.com/yb2915722928-cpu/rag_me/issues/8)。本工单承接同一 PDF 内数字页与扫描页的逐页处理、输出合并及跨路径诊断。

## What to build

调用方通过同一个公开解析入口传入同时包含数字页和扫描页的 PDF，无需先拆成两个文件：有质量可用文本层的页面利用文本层，需要识字的扫描页执行真实 OCR，最终按实际页序形成一篇 Markdown 正文及对应来源。

复用已完成的 PDF 提取和扫描识字能力，聚焦两条路径在一份文档中的协作，不引入新的上传服务、总路由、最终切块或问答链路。

## Acceptance criteria

- [ ] 使用固定混合样本，通过公开文件与字节入口均能获得数字页和扫描页的已知正文，并可按实际 PDF 页序回查各自来源。
- [ ] 页面内容按原始顺序合并，既不遗漏扫描页，也不重复加入同页的文本层结果与 OCR 结果；多页来源不串页。
- [ ] 有质量可用文本层的页面无需统一重做 OCR，需要识字的扫描页走已接通的实际路径。行为和运行记录说明所用路径，不以内部调用次数作为唯一验收依据。
- [ ] 质量说明明确文本非空不足以证明文字正确或结构完整，不新增能够自动判断所有业务事实和复杂版面的承诺。
- [ ] 固定样本中的已知标题、维护规则及阅读顺序得到核验；表格对应关系按实际支持程度检查，未恢复时如实说明，不能通过混合合并掩盖上游损失。
- [ ] 某页 OCR 不可用、执行失败或处理缺失时，诊断能够指出相关页面；不静默丢页后报告整篇处理完整，也不把错误信息拼入正文。
- [ ] 保持 PDF 页序、印刷页码及 OCR 图片坐标的语义边界；不因合并而生成虚假位置或坐标映射。
- [ ] 公开入口的行为测试覆盖两类页面共同成功及页面处理失败；采用真实解析和 OCR，固定样本来源、构造方式和摘要可追溯。
- [ ] 记录可复现的混合文档演示命令、环境与处理设置、预期和实际结果、已测耗时及局限；不把这一验收描述为完整 RAG 链路已经通过。
- [ ] 既有数字 PDF、纯扫描 PDF 与文本网页行为保持通过；DOCX 若已交付则一同运行回归，但不将 DOCX 的完成状态作为本工单开工依赖。
