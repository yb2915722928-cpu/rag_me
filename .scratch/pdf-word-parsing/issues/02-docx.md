# 02：按正文顺序解析 DOCX 并保留标题、表格对应关系和章节位置

**计划标签：** enhancement、ready-for-agent

## Parent

Part of [#8：实现 PDF 与 DOCX 解析并保留正文关系和来源](https://github.com/yb2915722928-cpu/rag_me/issues/8)。本工单承接 DOCX 原生结构、表格对应关系及章节内正文块来源。

## What to build

调用方通过已经建立的公开解析入口传入 DOCX 文件或字节，得到按原文阅读顺序组织的整篇 Markdown 正文。标题、段落和普通表格保持归属关系，并可从结果回到相应章节及正文块位置。

本工单直接复用数字 PDF 工单交付的公开调用和局部结果约定，业务代码继续集中在用户指定子模块内。它可以在扫描 PDF 工作进行的同时独立实现和验收。

## Acceptance criteria

- [ ] 文件与字节入口均能真实解析 DOCX，并沿用已建立的正文、来源、警告与失败表达；不改变已有数字 PDF 的可观察行为。
- [ ] 按原生正文顺序遍历标题、段落与表格，结果保留“标题 → 断电说明 → 设备周期表 → 重新启动说明”，表格仍位于两段说明之间。
- [ ] 已知标题层级保留在 Markdown 中，段落与表格的来源能够关联到所属章节。
- [ ] 普通表格保留表头和单元格对应关系，或转换为关系同样明确的文本；验收能分别确定“泵—每月”和“阀门—每季度”，不以全部词语出现代替关系检查。
- [ ] 来源信息保留文档标识、章节和正文块位置；明确段落、表格、标题的计数与重置规则，测试和使用说明与该规则一致。
- [ ] 章节内正文块序号不显示为 Word 页码或段落号；没有可靠页码时不生成推估页码，也不标为 PDF 页序。
- [ ] 损坏 DOCX 和整篇无可用正文有明确诊断；失败和警告不混入正文，不把旧版二进制 Word 当作已经支持的 DOCX。
- [ ] 通过公开入口运行真实转换，验证标题、阅读顺序、两组表格对应关系、章节位置及失败行为，尽量少用 mock。
- [ ] 固定样本进入现有样本组织，记录来源或构造方法、摘要与预期；依赖在项目环境声明并验证，说明公开入口的复现方式和普通表格支持边界。
- [ ] 说明优先使用 DOCX 的前提是调用方已经确认同版本、内容完整；不新增跨文件版本比对或自动优选功能。

## Blocked by

- 草案 01：打通数字 PDF 到 Markdown 正文与页序来源的解析。所需交付是公开入口与局部结果约定，不依赖 OCR 或 DOCX 以外的新服务。
