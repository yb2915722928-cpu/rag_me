# 01：打通数字 PDF 到 Markdown 正文与页序来源的解析

**计划标签：** enhancement、ready-for-agent

## Parent

Part of [#8：实现 PDF 与 DOCX 解析并保留正文关系和来源](https://github.com/yb2915722928-cpu/rag_me/issues/8)。本工单承接父规格中公共调用、数字 PDF、来源信息及相关失败行为。

## What to build

调用方通过 PDF 与 Word 解析模块的公开入口，传入数字 PDF 文件或已经取得的文件字节，得到整篇 Markdown 正文，以及能对应回实际 PDF 页序的来源信息。真实输入可以独立演示和验收，后续 DOCX 与 OCR 分支沿用本工单建立的局部结果约定。

解析业务代码留在用户指定的 PDF 与 Word 解析子模块；依赖声明、测试和固定样本沿用仓库现有组织方式。入口、结果表达、实际提取与行为测试随这一条可用路径一起交付，不提前建设跨模块框架，也不要求修改已有文本与网页转换行为。

## Acceptance criteria

- [ ] 提供本地文件及已有字节的公开调用方式；字节入口明确取得格式和来源。外部参数在入口完成必要校验，两个入口使用相同的内容处理行为。
- [ ] 成功结果提供整篇 Markdown 正文及与输出内容对应的来源信息；警告与失败原因独立于正文。局部结果约定能由后续 DOCX 和 OCR 分支直接使用，不依赖尚未完成的上传服务或总路由。
- [ ] 用真实数字 PDF 提取标题文字、断电规则和检查周期，通过已知原文检查，不只断言结果非空。
- [ ] 保留页面原始先后顺序，内容能追溯到实际 PDF 页序。至少一个多页或页码标记不同的固定样本证明来源没有串页，未把总页数或印刷页码当作内容所在页。
- [ ] 对标题与阅读顺序进行样本核验，明确文本层提取不等于已恢复任意标题层级、双栏或表格结构，不作无损恢复承诺。
- [ ] 在 OCR 尚未实现时，真实扫描样本不能通过图片引用或占位冒充文字正文；整篇没有可用文字时返回明确失败或明确需要识字的诊断。
- [ ] 无法读取、不支持格式、损坏 PDF 和整篇无可用正文均有明确结果；失败不提供可被当作成功正文的错误字符串。
- [ ] 测试通过公开入口调用真实解析实现，覆盖文件与字节输入、正文、来源及失败行为，不绑定内部辅助函数或调用次数。
- [ ] 固定输入能由仓库验收环境取得，记录样本来源或构造方法、摘要和预期事实；新增样本核对 Git 收录状态。
- [ ] 依赖在项目环境声明并验证；记录复现命令与已验证范围，现有文本与网页行为测试仍通过。
