# 03：通过真实 OCR 解析扫描 PDF 并核验关键正文

**计划标签：** enhancement、ready-for-agent

## Parent

Part of [#8：实现 PDF 与 DOCX 解析并保留正文关系和来源](https://github.com/yb2915722928-cpu/rag_me/issues/8)。本工单承接扫描页实际识字、来源追溯、失败诊断及识字质量核验。

## What to build

调用方通过既有公开入口传入纯扫描 PDF，可以实际执行页面渲染与 OCR，取得图片中的正文并追溯到原文档及 PDF 页序。路径必须真实可运行，不能只返回图片引用、空扩展点或模拟识字结果。

选择一条可复现的实际识字路径并记录所需环境、依赖和限制，不开展多引擎全面比较。扫描正文、OCR 坐标及扫描表格关系分别核验；识字完成与内容质量通过保持区别。

## Acceptance criteria

- [ ] 在已经建立的公开文件和字节入口中接通纯扫描 PDF 的实际渲染与 OCR，结果采用既有整篇正文、来源及独立诊断约定。
- [ ] 至少一个真实扫描样本的已知关键正文通过原文核验；断电规则、检查周期等事实不能只靠输出非空或调用无异常证明。
- [ ] 测试或实验记录区分文本层直接提取结果、实际 OCR 输出和关键内容核验结果，图片引用或占位不充当取得的正文。
- [ ] 输出内容保留文档及实际 PDF 页序来源，多页扫描输入不串页；页级问题能够定位到相关页面。
- [ ] OCR 不可用、执行失败或整篇没有可用正文时提供明确诊断，失败不以成功正文交给后续处理；未运行或跳过的识字验证不标为通过。
- [ ] 核验关注否定词、数字和单位；保留历史扫描样本及其错漏观察，若更换处理路径，应重新运行并如实报告结果，不改写原样本或把尚未运行的方案写成修复成功。
- [ ] 扫描表格使用明确可核对的样本检查设备与周期对应关系。仅获得平铺词语时，在实际结果或实验记录中明确关系未恢复，不按表格结构解析成功记账；不要求自动理解或校正所有业务事实。
- [ ] 若识字路径输出词框，明确位置属于输入图片像素及相应渲染比例；未经映射不宣称是原 PDF 坐标，不把词框存在当作表格关系恢复证明。
- [ ] 通过公开入口调用真实识字路径，固定输入、依赖版本、处理设置、预期与实际及已测耗时可复核。mock 不作为扫描解析或 OCR 质量通过的证据。
- [ ] 业务代码集中于指定解析子模块；依赖与样本遵循项目现有流程，记录实际需要的环境和复现命令，现有数字 PDF 行为仍通过。
- [ ] 本工单交付纯扫描 PDF 的完整可用路径；数字页与扫描页混合时的逐页派发、合并和跨路径失败行为由混合 PDF 工单验收。
