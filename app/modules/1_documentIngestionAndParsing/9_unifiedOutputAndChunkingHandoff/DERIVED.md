# 图片与媒体派生文字交接

通过统一公开入口 `adapt_result(native_result, business_id=None, version=None)` 接收第6节图片或第7节音视频的原生 `ConversionResult`，再使用 `export_json(report, path)` 导出 UTF-8 JSON。适配不读原文件、不重新解析、不调用 API，也不修改原结果。

## 正文、单元与来源

正文使用上游完整 `text`，`body_format="text"`。媒体正文包含上游已生成的时间及模态标记，不能以片段单元重新拼接替代。`content`、`no_text`、`uncertain`、`failed` 保持原状态；正常空文字为 `""`，失败正文为 `null` 且没有内容单元。

| 输入 | 内容单元 | 来源及对齐 |
| --- | --- | --- |
| 图片 OCR | `kind="ocr"`，整图文字 | `Source.kind="image"`，`alignment="document"` |
| 图像描述 | `kind="describe"`，画面概括 | 同上；概括不表示图片原文 |
| 视觉理解 | `kind="understand"`，针对原问题的解释 | 同上；不确定解释仍为 `uncertain` |
| 媒体语音 | 每个上游 `audio` 片段一个单元 | `media_segment`，保留实际起止时间及 `time_precision` |
| 媒体画面 | 每个上游 `video` 片段一个单元 | 同上；保持与语音分开，`alignment="unmapped"` |

这些输入没有正文字符映射，所有单元的 `body_span` 均为 `null`；不搜索正文来猜偏移，不补 OCR 字框或逐词时间。媒体单元没有上游父子关系，`parent_id` 保持 `null`。

图片来源保留字节 SHA-256、尺寸、格式、位置、已知文档标识及业务版本、PDF 页序或演示页、原图裁剪映射。未知事实保持 `null`，裁剪框按上游左上原点、右下不含的像素坐标导出为 JSON 数组。图片的任务、原问题、请求模型、响应模型与提示词版本保存在文档 `metadata`。

媒体文档有一个完整 `media` 来源，每个片段再有独立 `media_segment` 来源。片段来源同时保留原媒体字节版本及媒体标识、版本、时长、音轨等已知事实，以及片段种类、实际起止时间、时间精度和说话人。单元 `metadata` 保留模型、提示词版本、说话人、精度与核验备注；`structure.segments` 保留完整原生片段投影。未知说话人及未披露的模型版本仍为 `null`。

## 状态与核验

`requires_review` 沿用上游。技术上有可用派生文字不表示已经对照原图或原媒体核验；没有文字也不证明原资料没有相应信息。

- 图片核验事项以 `level="review"` 诊断保留原代码和消息，关联图片来源及实际存在的内容单元。
- 媒体整体核验事项关联媒体来源，片段核验备注关联对应单元及片段来源。不会将整体限制错误归到某个片段。
- 警告以 `upstream_warning` 保留完整消息及文档、来源引用，不拼进正文。
- 错误保留原代码、消息和完整 `details`；媒体错误还保留失败阶段和实际起始时间。中途失败不恢复上游已撤回的部分正文或片段。

显式业务标识与版本只写入交接文档。文件名、SHA-256、图片父文档标识或媒体版本不会自动成为这份交接文档的业务标识与版本。来源、结构及核验信息使用独立投影；文档、来源及单元共用调用方传入的 `IdAllocator`，ID 仅在本次报告内使用。

## 验证

```powershell
python -m unittest tests.test_handoff_derived tests.test_handoff_text_web -v
```

测试复用现有图片 HTTP 服务、媒体 HTTP 服务及固定样本，通过真实文件／字节解析入口生成结果，再调用公开交接入口、导出 JSON 并回读。覆盖三类图片任务、原图裁剪、语音／画面片段、无文字、不确定及 HTTP／中途失败，核验完整正文、来源、状态、引用和输入不变。交接期间服务保持运行，请求数不增加；不访问云端服务。
